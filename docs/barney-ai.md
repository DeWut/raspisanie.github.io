# Барни AI: локальная модель, память и обучение

## Архитектура

Барни использует три независимых слоя:

1. **Инструменты приложения** — расписание, ДЗ, дедлайны, преподаватели, аудитории и профиль. Они остаются детерминированными и имеют приоритет над моделью.
2. **Локальная база знаний** — проверенные справочные ответы в `backend/data/barney_knowledge_ru.json`. Для свободного вопроса подходящие фрагменты добавляются в системный контекст (RAG).
3. **LFM3** — свободный разговор, объяснения, учебные планы, помощь с формулировками и продолжение диалога. Если модель недоступна, Барни сообщает об ограничении и использует локальные правила.

Модель не должна самостоятельно менять расписание, ДЗ, настройки, права, профили или записи Neon.

## Включение локальной LFM3

На компьютере должны работать Ollama, модель и защищённый proxy:

```powershell
ollama pull lfm3
ollama list
```

В существующем защищённом proxy используется `OLLAMA_PROXY_TOKEN`; он должен совпадать с `OLLAMA_API_KEY` в Render. Никогда не публикуй этот токен, не коммить его в Git и не открывай напрямую порт 11434.

Render environment:
- `OLLAMA_BASE_URL` — HTTPS Funnel URL без завершающего слеша.
- `OLLAMA_API_KEY` — тот же секрет, что `OLLAMA_PROXY_TOKEN`.
- `OLLAMA_MODEL=lfm3`.

В личном Telegram-чате свободные вопросы идут в LFM3, если локальные правила не распознали специальную команду. В Mini App используется тот же необязательный endpoint. Если компьютер выключен или потерял сеть, fallback продолжает работать.

## Подготовка обучения

Обучение не происходит автоматически после каждого сообщения. Это опасно: пользовательские ошибки, спам, персональные данные и выдуманные ответы могут испортить модель.

### Локальный учитель на Ollama

В `scripts/barney_ai/BARNEY_AI.bat` есть режим **[6] LOCAL TEACHER**. Он обращается к локальному Ollama API (`127.0.0.1:11434`) и просит модель `lfm3` предложить учебные пары «вопрос — хороший ответ». Ты можешь принять пример, отредактировать ответ или отклонить его. Только принятые примеры записываются в `approved_dialogues.jsonl`.

Это не автоматическое изменение весов и не полноценный независимый учитель: если учитель и ученик — одна и та же LFM3, модель в основном генерирует варианты собственного поведения. Главный вклад в качество дают твои исправления, проверенные факты и хорошие сценарии. Для более сильного teacher можно позднее выбрать другую модель, если она помещается в ресурсы ноутбука; поменять имя можно через переменную `BARNEY_TEACHER_MODEL`.

Контролируемый цикл:
1. Запусти Ollama и проверь `ollama list`.
2. Открой `BARNEY_AI.bat` → **[6] LOCAL TEACHER**, укажи тему и количество примеров.
3. Проверь каждую пару, исправь слабые ответы или отклони их.
4. Запусти **[3] Prepare dataset**, затем **[4] TRAIN BARNEY**.
5. После обучения проверь ответы и только затем используй **[7] Export trained model to Ollama**.

1. Добавь исправленный пример в `data/barney_training/approved_dialogues.jsonl`. Формат — одна JSON-строка на пример:
   ```json
   {"user":"Объясни API простыми словами","assistant":"API — это согласованный способ, по которому программы обмениваются запросами и ответами. Например, Mini App спрашивает backend о расписании."}
   ```
2. Проверь, что в нём нет имён, телефонов, адресов, Telegram ID, токенов, паролей и приватных сообщений третьих лиц.
3. Пересобери датасет:
   ```powershell
   python scripts/barney_ai/prepare_dataset.py
   ```
4. Установи зависимости обучения в отдельном Python venv. PyTorch лучше устанавливать под конкретную версию CUDA с официального установщика PyTorch; затем остальные закреплённые версии:
   ```powershell
   pip install -r scripts/barney_ai/requirements-training.txt
   ```
5. Запусти `scripts/barney_ai/BARNEY_AI.bat` и выбери пункт **[4] TRAIN BARNEY**. Альтернативно — вручную:
   ```powershell
   python scripts/barney_ai/train_lfm3_lora.py --epochs 2 --batch-size 1 --grad-accum 16 --max-length 512 --lora-rank 8 --merge
   ```
6. Сравни adapter на отложенной выборке и вручную проверь ответы. Не заменяй рабочую модель до проверки.

### Профиль ноутбука RTX 4050 / 36 GB RAM

Мобильная RTX 4050 обычно имеет 6 GB GDDR6 VRAM. Сверь фактический объём через `nvidia-smi`: производитель ноутбука может задавать разные лимиты мощности, но объём видеопамяти у RTX 4050 Laptop GPU по спецификации NVIDIA — 6 GB. 36 GB системной RAM помогают загрузке и CPU-операциям, но не превращаются в VRAM.

Для первого запуска используй подготовленный `scripts/barney_ai/BARNEY_AI.bat`: он создаёт venv, проверяет CUDA, собирает датасет, запускает LoRA с batch=1, gradient accumulation=16, max_length=512 и rank=8, затем объединяет адаптер на CPU и экспортирует GGUF в Ollama. Перед запуском закрой игры и другие GPU-приложения, подключи ноутбук к питанию и оставь запас свободного места на диске (веса, кэш Hugging Face, checkpoints и GGUF занимают несколько гигабайт).

Если CUDA OOM:
1. Уменьши `--max-length 512` до 256 в BAT.
2. Не увеличивай batch size; оставь 1.
3. Уменьши `--lora-rank 8` до 4.
4. Закрой процессы, использующие GPU, и повтори запуск.

Это стартовая конфигурация, а не гарантия, что конкретная версия драйвера, PyTorch и CUDA поместится в 6 GB. Первый запуск проверь по фактическому пику памяти и логам. На CPU обучение может быть крайне медленным.

## Экспорт в Ollama

Скрипт сохраняет LoRA adapter. Не предполагай, что Ollama сможет загрузить любой adapter напрямую: поддержка зависит от архитектуры и формата. Для LFM3 проверь актуальную инструкцию Liquid AI и llama.cpp. Надёжный общий путь — объединить adapter с исходным HF checkpoint (опция `--merge`), затем конвертировать merged checkpoint в поддерживаемый LFM3 GGUF и импортировать GGUF через Modelfile. После этого меняется только `OLLAMA_MODEL` на локальное имя созданной модели.

Пример экспорта объединённой модели в GGUF (после установки актуального llama.cpp и его Python-зависимостей):

```powershell
python .\llama.cpp\convert_hf_to_gguf.py .\training\barney-lfm3-lora-merged --outfile .\training\barney-lfm3.gguf --outtype q8_0
```

Создай рядом файл `Modelfile`:

```text
FROM ./barney-lfm3.gguf
PARAMETER temperature 0.35
PARAMETER top_p 0.9
PARAMETER repeat_penalty 1.1
SYSTEM Ты Барни — спокойный и доброжелательный учебный помощник СПбГЛТУ. Отвечай по-русски, кратко и по существу. Не выдумывай учебные данные.
```

Импортируй и проверь:

```powershell
ollama create barney-lfm3 -f .\training\Modelfile
ollama run barney-lfm3
```

Если тест прошёл, укажи `OLLAMA_MODEL=barney-lfm3` в Render. Оставь исходную `lfm3` модель до тех пор, пока новая не проверена. Для GGUF используй сборку llama.cpp с поддержкой LFM3; опубликованные GGUF LFM3 подтверждают поддержку этой архитектуры, но конвертацию именно твоего merged checkpoint нужно проверить отдельно.
