# Барни AI: локальная модель, память и обучение

## Архитектура

Барни использует три независимых слоя:

1. **Инструменты приложения** — расписание, ДЗ, дедлайны, преподаватели, аудитории и профиль. Они остаются детерминированными и имеют приоритет над моделью.
2. **Локальная база знаний** — проверенные справочные ответы в `backend/data/barney_knowledge_ru.json`. Для свободного вопроса подходящие фрагменты добавляются в системный контекст (RAG).
3. **LFM3** — свободный разговор, объяснения, учебные планы, помощь с формулировками и продолжение диалога. Если модель недоступна, Барни сообщает об ограничении и использует локальные правила.

Модель не должна самостоятельно менять расписание, ДЗ, настройки, права, профили или записи Neon.

## Включение локальной LFM3

На компьютере должны работать Ollama, модель и защищённый proxy:

```powershell
ollama pull lfm3
ollama list
```

В существующем защищённом proxy используется `OLLAMA_PROXY_TOKEN`; он должен совпадать с `OLLAMA_API_KEY` в Render. Никогда не публикуй этот токен, не коммить его в Git и не открывай напрямую порт 11434.

Render environment:
- `OLLAMA_BASE_URL` — HTTPS Funnel URL без завершающего слеша.
- `OLLAMA_API_KEY` — тот же секрет, что `OLLAMA_PROXY_TOKEN`.
- `OLLAMA_MODEL=lfm3`.

В личном Telegram-чате свободные вопросы идут в LFM3, если локальные правила не распознали специальную команду. В Mini App используется тот же необязательный endpoint. Если компьютер выключен или потерял сеть, fallback продолжает работать.

## Подготовка обучения

Обучение не происходит автоматически после каждого сообщения. Это опасно: пользовательские ошибки, спам, персональные данные и выдуманные ответы могут испортить модель. Используется контролируемый цикл:

1. Добавь исправленный пример в `data/barney_training/approved_dialogues.jsonl`.
2. Проверь, что в нём нет имён, телефонов, адресов, Telegram ID, токенов, паролей и приватных сообщений третьих лиц.
3. Пересобери датасет:
   ```powershell
   python scripts/barney_ai/prepare_dataset.py
   ```
4. Установи зависимости обучения в отдельном Python venv. PyTorch лучше устанавливать под конкретную версию CUDA с официального установщика PyTorch; затем остальные закреплённые версии:
   ```powershell
   pip install -r scripts/barney_ai/requirements-training.txt
   ```
5. Запусти LoRA SFT:
   ```powershell
   python scripts/barney_ai/train_lfm3_lora.py --epochs 2 --batch-size 1 --grad-accum 8
   ```
6. Сравни adapter на отложенной выборке и вручную проверь ответы. Не заменяй рабочую модель до проверки.

Ожидается CUDA GPU с достаточной видеопамятью. На CPU обучение может быть крайне медленным. Если на ПК нет подходящей видеокарты, можно запускать обучение в бесплатной облачной GPU-среде, если она доступна, а готовый результат скачать.

## Экспорт в Ollama

Скрипт сохраняет LoRA adapter. Не предполагай, что Ollama сможет загрузить любой adapter напрямую: поддержка зависит от архитектуры и формата. Для LFM3 проверь актуальную инструкцию Liquid AI и llama.cpp. Надёжный общий путь — объединить adapter с исходным HF checkpoint (опция `--merge`), затем конвертировать merged checkpoint в поддерживаемый LFM3 GGUF и импортировать GGUF через Modelfile. После этого меняется только `OLLAMA_MODEL` на локальное имя созданной модели.
