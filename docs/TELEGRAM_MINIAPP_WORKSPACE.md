# Telegram Mini App — отдельная рабочая ветка

Рабочая ветка: `work/telegram-miniapp`

Базовая точка ответвления: `feature/campus-map-photorealism` (снимок на момент создания ветки).

## Что относится к Mini App

- `miniapp/index.html`, `miniapp/week.html` — страницы приложения.
- `miniapp/app.js`, `miniapp/styles.css`, `miniapp/native-bridge.js` — интерфейс, расписание, состояние и интеграция с WebView.
- `miniapp/map3d.html`, `miniapp/map3d.js`, `miniapp/map3d-geometry.js` — карта кампуса и геометрия.
- `miniapp/vendor/**`, `miniapp/assets/**` — локальные библиотеки и ресурсы.
- `data/groups.json`, `data/<group-id>.json`, `data/campus.json`, `data/campus-park-scene.json` — данные, которые приложение читает.

## Как работает интеграция с Telegram

Mini App — статический веб-интерфейс, открываемый внутри Telegram WebView по публичному HTTPS URL. Он подключает официальный Telegram Web App bridge и может работать в обычном браузере. Кнопку открытия показывает бот через `WEBAPP_URL`. Сейчас выбранная группа хранится локально; отправка выбранной EIOS-группы боту выполняется отдельным действием пользователя.

## Локальная проверка

Из корня репозитория:

```bash
python -m http.server 8000
```

Открыть `http://127.0.0.1:8000/miniapp/index.html`. Для проверки внутри Telegram нужен опубликованный HTTPS URL; localhost на телефоне не доступен Telegram WebView как публичный адрес.

Проверки JavaScript/геометрии:

```bash
node --check miniapp/app.js
node --check miniapp/map3d.js
node --check miniapp/map3d-geometry.js
node --test tests/map3d-geometry.test.js
```

## Правила изменений

1. Не менять `backend/src/bot.rs` и backend-миграции для локальных UI-изменений.
2. Если нужен новый API endpoint или Telegram Web App контракт, описать его в PR и согласовать с `work/telegram-bot`.
3. Не коммитить пользовательские токены, ключи картографических сервисов и приватные планы помещений.
4. Для включения в общую линию создавать PR в `feature/campus-map-photorealism`; сначала проверить, что данные и backend-контракты совместимы.
5. Не мержить эту ветку напрямую в `main` без интеграционной проверки.

## Важное про планы этажей

Интерактивные планы этажей — отдельная функция поверх справочника корпусов: корпус → этаж → план → кабинеты. Схема должна хранить масштабируемое изображение/векторный план и отдельные контуры кабинетов с номером, названием и назначением. Фотография плана эвакуации может быть исходником для оцифровки, но не должна автоматически публиковаться как готовая точная схема: сначала нужно выровнять перспективу, проверить масштаб, вручную сверить стены/кабинеты и проверить номера. Не публиковать закрытые зоны, точки доступа, охранные помещения или другую чувствительную инфраструктуру без разрешения владельца здания.
