# BARNEY-NANO — компактный университетский помощник

BARNEY-NANO — экспериментальная компактная модель для университетских сценариев. Она не заменяет backend, Neon или инструменты приложения. Модель формирует язык и интерпретирует намерения; актуальное расписание, аудитории, профили, группы и другие данные по-прежнему берутся только из существующего backend.

## Выбранная стратегия

- Учитель: локальная LFM3 через Ollama.
- Ученик: HuggingFaceTB/SmolLM2-360M-Instruct (около 360 млн параметров).
- Обучение: supervised fine-tuning LoRA на проверенных ответах, сгенерированных LFM3 и одобренных человеком.
- Экспорт: объединённый checkpoint → GGUF → квантизация после benchmark.
- Первый deployment target: экспериментальный отдельный inference-процесс. Существующий Telegram backend, Neon и Mini App не заменять до успешного теста.

Исходная SmolLM2 в основном ориентирована на английский, поэтому качество русского языка — отдельный критерий benchmark, а не предположение.

## Автоматическая установка Windows

1. Распаковать репозиторий в постоянную папку, например C:\AI\BARNEY-NANO.
2. Запустить scripts\barney_nano\BARNEY_NANO.bat.
3. Выбрать [1] Automatic installation / repair.
4. Дождаться завершения. Установщик создаёт .venv-barney-nano, ставит Python 3.11 x64 через winget при необходимости, устанавливает Ollama через winget, ставит PyTorch CUDA 12.8 и Python-зависимости, загружает student model в Hugging Face cache и пытается скачать lfm3 через Ollama.
5. Выбрать [2] Hardware and dependencies check. Для обучения обязательно CUDA: True и обнаруженная NVIDIA GPU.

Требования:
- Windows x64 и подключение к интернету.
- Windows Package Manager (winget, обычно поставляется с App Installer).
- Достаточно свободного места для Python, библиотек и весов моделей. Загрузка моделей может занимать несколько гигабайт.
- Актуальный NVIDIA display driver. Установщик намеренно не заменяет системный драйвер без подтверждения пользователя; если CUDA недоступна, обновить драйвер с официального сайта NVIDIA, перезагрузить Windows и повторить пункт [1].
- Установщик ведёт лог в logs\barney-nano-install-YYYYMMDD-HHMMSS.log.

Установщик можно запускать повторно: он использует существующее виртуальное окружение и кеш моделей, затем проверяет/доустанавливает компоненты.

### Ограничение LFM3

Установщик пробует ollama pull lfm3, но успешная установка Ollama не гарантирует, что конкретная модель доступна для Windows в установленной версии Ollama. Если pull завершится ошибкой, установщик не подменяет LFM3 другой моделью. В этом случае локальная подготовка student и CUDA может быть завершена, но генерация teacher dataset остаётся недоступной до решения проблемы совместимости модели.

### Что не устанавливается принудительно

NVIDIA display driver и системные компоненты, требующие перезагрузки/администраторского подтверждения, не заменяются автоматически. Также не устанавливается Git: он не нужен для запуска локального pipeline после распаковки архива. winget должен быть доступен; если его нет, установите/обновите App Installer из Microsoft Store и повторите запуск.

## Цикл дистилляции

1. Запустить [3] Generate candidates with LFM3 teacher. Начать с 20–50 примеров.
2. Проверить каждую пару через [4] Review / approve dataset. Исправлять неточные ответы, отклонять сомнительные. Не обучать на сырых непроверенных диалогах.
3. Для первого smoke test требуется минимум 30 одобренных примеров; для осмысленной специализации ориентир — сотни и затем тысячи разнообразных, качественных примеров.
4. Запустить [5] Train BARNEY-NANO. Стартовый профиль: LoRA rank 8, batch 1, gradient accumulation 16, context 512, 3 эпохи. Это стартовая настройка, не гарантия отсутствия OOM.
5. Запустить [6] Evaluate trained adapter. Не использовать обучающие примеры как benchmark.
6. Только после проверки запускать [7] Merge adapter for GGUF export.

## Что должно оставаться вне весов модели

Не зашивать в модель изменяемые сведения о конкретных студентах, преподавателях, расписании, оценках, аудиториях и событиях. Они должны поступать из backend. Не включать в датасет Telegram ID, имена, телефоны, адреса, приватные переписки, пароли, API-ключи и другие секреты. Пользовательские действия выполняются только существующими backend-инструментами с проверкой прав.

## Следующий этап: GGUF и deployment

После локального benchmark:
1. Установить актуальную сборку llama.cpp.
2. Конвертировать training\barney-nano-merged через convert_hf_to_gguf.py.
3. Проверить модель локально через llama-server.
4. Замерить память и скорость на целевой платформе.
5. Только если тест пройден, подключать inference к backend. Не менять существующий Telegram backend и Mini App до успешной проверки.
