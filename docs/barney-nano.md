# BARNEY-NANO — компактный университетский помощник

BARNEY-NANO — экспериментальная компактная модель для университетских сценариев. Она не заменяет backend, Neon или инструменты приложения. Модель формирует язык и интерпретирует намерения; актуальное расписание, аудитории, профили, группы и другие данные по-прежнему берутся только из существующего backend.

## Архитектура и ограничения

- Учитель для дистилляции: LFM3 через локальный Ollama.
- Ученик: HuggingFaceTB/SmolLM2-360M-Instruct (около 360 млн параметров).
- Обучение: supervised fine-tuning LoRA на проверенных примерах.
- Рабочий backend: Rust; уже передаёт OLLAMA_MODEL в существующий Ollama API-клиент. Neon, команды Telegram и Mini App не требуют миграции для смены имени модели.
- Новая модель не загружается на Render. Render остаётся хостом backend; inference выполняется на Ollama-хосте, доступном через существующий защищённый HTTPS proxy/Tailscale Funnel.
- Исходная SmolLM2 в основном ориентирована на английский. Качество русского языка и правильность поведения нужно измерять, а не предполагать.

Важное отличие: BARNEY-NANO (SmolLM2) и текущая LFM3 — разные архитектуры и веса. Экспорт/импорт новой модели проверяется на локальном Ollama. Если Ollama не примет Safetensors checkpoint или модель не ответит, публикация будет заблокирована; текущая production-модель не затрагивается.

## Автоматическая установка Windows

1. Распаковать репозиторий в постоянную папку, например C:\AI\BARNEY-NANO.
2. Запустить scripts\barney_nano\BARNEY_NANO.bat.
3. Выбрать [1] Automatic installation / repair.
4. Установщик проверяет Python 3.11 x64 и Ollama, ищет обновления; создаёт или повторно использует .venv-barney-nano; проверяет CUDA PyTorch, Python dependencies и Hugging Face model cache; пытается запустить Ollama и проверить/скачать LFM3.
5. Если компонент уже установлен и актуален, этап получает [SKIP]. Повторный запуск не удаляет venv, cache, датасет, адаптеры и releases.
6. Выбрать [2] Hardware and dependencies check. Для обучения обязательно CUDA: True и обнаруженная NVIDIA GPU.

Требования:
- Windows x64, интернет и Windows Package Manager (winget, обычно поставляется с App Installer).
- Актуальный NVIDIA display driver. Системный драйвер не заменяется автоматически; после его ручного обновления может потребоваться перезагрузка.
- Свободное место на диске для Python-пакетов, базовой модели, датасета, checkpoints и релизных копий.
- Установщик ведёт лог в logs\barney-nano-install-YYYYMMDD-HHMMSS.log.

## Цикл обучения и выпуска

### 1. Собрать и проверить данные

1. [3] Generate candidates with LFM3 teacher — начни с 50–100 примеров.
2. [4] Review / approve dataset — проверяй каждую пару, исправляй неточности и отклоняй слабые ответы.
3. Минимум 30 примеров нужен только для технического smoke test. В текущем release gate BARNEY-NANO установлено не менее 300 проверенных примеров для допуска к production. Это проектное условие качества корпуса, не гарантия качества модели.

В датасете не должно быть Telegram ID, имён и контактов частных лиц, приватных переписок, паролей, API-ключей или других секретов.

### 2. Обучить и получить метрики

Запусти [5] Train BARNEY-NANO. Успешный запуск сохраняет:
- LoRA adapter;
- training_run.json с GPU, параметрами обучения, числом одобренных примеров, fingerprint датасета, trainable parameters и eval loss;
- trainer_state.json с историей обучения.

Скрипт показывает количество обучаемых параметров LoRA и их долю от общего числа параметров модели. Это доля изменяемых параметров, а не процент «готовности» или качества.

После обучения старые benchmark, human-QA и candidate pointers сбрасываются. Перед выпуском автоматика дополнительно сравнивает SHA-256 текущего approved.jsonl с fingerprint датасета из training_run.json; если датасет изменился после обучения, отчёт выставит NEEDS_RETRAINING и не позволит создать/опубликовать кандидат. Предыдущие именованные модели Ollama не удаляются и не перезаписываются.

### 3. Сравнить ответы и вручную проверить качество

1. [6] Evaluate trained adapter сравнивает базовую и дообученную модели на фиксированных русскоязычных университетских запросах. Результат сохраняется в training\barney-nano-benchmark.txt и training\barney-nano-benchmark.json.
2. [9] Readiness report показывает:
   - количество параметров базовой модели и обучаемых LoRA-параметров;
   - долю обучаемых параметров;
   - размер кеша базовой модели, adapter weights, папки adapter/checkpoints, merged checkpoint и Ollama candidate;
   - отношение размера adapter weights к размеру кеша базовой модели;
   - число уникальных одобренных запросов, eval loss, скорость генерации и benchmark status;
   - долю пройденных release gates.
3. [10] Review benchmark answers показывает каждый ответ BARNEY-NANO. Для выпуска нужно вручную подтвердить каждый тест: правильность, русский язык, отсутствие выдуманных данных и безопасное поведение. Результат привязывается к точному hash benchmark. После нового обучения старое подтверждение нельзя использовать.

Процент readiness — это процент пройденных контрольных пунктов, а не оценка точности модели. Eval loss, скорость генерации и размер файла также не заменяют человеческую оценку ответов.

### 4. Создать локальную версию-кандидат

Запусти [11] Build versioned Ollama candidate.

Действия:
1. Проверяет, что ручная проверка относится к текущему benchmark и все случаи одобрены.
2. Объединяет LoRA с базовой моделью в отдельной папке training\releases\rc-...
3. Создаёт уникальную версию Ollama с тегом вида barney-nano:rcYYYYMMDDHHMMSS.
4. Выполняет пробный запрос через локальный Ollama API.
5. Сохраняет manifest кандидата и обновляет readiness report.

Ollama официально поддерживает импорт Safetensors из каталога весов через FROM /path/to/safetensors/directory и ollama create; фактическая совместимость именно этой объединённой модели проверяется нашим локальным smoke test. См. https://github.com/ollama/ollama/blob/main/docs/import.mdx.

На этом этапе:
- тег lfm3 не изменяется;
- OLLAMA_MODEL в Render не изменяется;
- production backend и пользователи не переключаются;
- при неудачном импорте кандидат не продвигается.

### 5. Отправить обновление в работающий backend

Только после статуса READY_FOR_PROMOTION разрешается запускать [12] Promote candidate to live Render backend.

Перед переключением скрипт:
- требует Render Service ID и API key (ввод ключа скрыт; он не записывается в файлы репозитория и не должен передаваться в чат);
- проверяет, что сервис называется spbftuit-smart-campus-api и имеет тип Web Service;
- проверяет прямые переменные OLLAMA_MODEL, OLLAMA_BASE_URL и OLLAMA_API_KEY;
- проверяет доступность нового кандидата через тот же HTTPS proxy, которым пользуется backend;
- отдельно проверяет доступность текущей production-модели как цели отката;
- просит вручную ввести слово PROMOTE перед первым изменением production.

После подтверждения скрипт меняет только одну переменную — OLLAMA_MODEL — и отдельно запускает Render deploy. Остальные env vars не переписываются. Render API предоставляет отдельный endpoint для обновления одной переменной; он работает только с переменными, заданными непосредственно на сервисе, а не в linked environment group. Поэтому если переменная лежит в группе, скрипт безопасно остановится, а не будет заменять весь список переменных. См. https://api-docs.render.com/reference/update-env-var и https://api-docs.render.com/reference/update-env-vars-for-service.

После deploy скрипт ждёт статус live и проверяет /health. При явной ошибке deploy или неуспешной проверке здоровья он пытается вернуть прежнее значение OLLAMA_MODEL и запустить rollback deploy. При неопределённом статусе не делает рискованных повторных изменений: нужно проверить Render Deploys и затем принять решение.

Скрипт не копирует модель на Render. Новая версия должна оставаться установленной на Ollama-хосте, доступном по существующему защищённому proxy. На хосте должны оставаться и новая, и предыдущая production-модель.

### 6. Откат

[13] Roll back to previous live model:
- читает сохранённое имя предыдущей модели из training\barney-nano-render-deploy.json;
- проверяет, что прежняя модель всё ещё отвечает через proxy;
- просит ввести ROLLBACK;
- меняет только OLLAMA_MODEL обратно, запускает deploy и проверяет /health.

Не удаляй старый тег из Ollama, пока новая модель используется или пока не завершилась проверка после обновления.

## Файлы релиза

- training\barney-nano-readiness.md — читаемый отчёт о готовности.
- training\barney-nano-readiness.json — машинный отчёт с метриками и хешами.
- training\barney-nano-benchmark.* — ответы базовой и дообученной моделей.
- training\barney-nano-qa.json — ручная проверка benchmark.
- training\barney-nano-candidate.json — указатель на текущего локального кандидата.
- training\releases\ — versioned merged checkpoints и manifests.
- training\barney-nano-render-deploy.json — сохранённые значения для отката Render.

Не коммить содержимое data/barney_nano и training: там будут пользовательский датасет, веса, checkpoints, токенизатор и локальные модели. Храни их на своём компьютере или в закрытом хранилище.

## Границы безопасного переключения

Не обучать модель на изменяемых данных о расписании, оценках, аудиториях и конкретных студентах. Для этих сведений источником истины остаётся backend/Neon с проверкой прав. BARNEY-NANO влияет только на свободный текстовый ответ; команды расписания, ДЗ, профиля, группы и действия Mini App не должны переноситься в модельные веса.

Даже после успешного переключения backend /health проверяет доступность самого Rust API и базы данных, а не качество каждой генерации. После релиза отдельно проверь несколько диалогов в Telegram и наблюдай за логами. При ухудшении качества верни предыдущую модель через пункт [13].
