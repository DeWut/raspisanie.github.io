## Как данные доходят до экрана

- `map3d.js` загружает `campus-park-scene.json` и `campus.json`.
- `map3d-geometry.js` преобразует сырую геометрию в наборы `ground`, `footprints`, `solid` и `highlight`.
- `map3d.js` передаёт эти наборы в MapLibre через `syncSceneData()`.
- Слой `bld` рисует 3D-объёмы из `solid`. Здания без подтверждённой высоты остаются плоскими контурами. Не выдумывай высоту ради красивой картинки.
- Маркеры и карточки корпусов берутся из `campus.json`, а не из SVG-планов.
- Планы этажей — отдельные векторные SVG из двух JS-файлов. Реестр `window.CAMPUS_FLOORPLANS` индексируется номером корпуса.
- Для корпуса № 1 оставь только исходное фото `miniapp/assets/campus-main-building-aerial.jpg`, подпись автора и лицензию. Динамическая галерея Wikimedia для него намеренно отключена. Не добавляй случайные изображения из категории Commons.

## Критическое правило обновления кэша

После изменения карты синхронно обновляй:
1. query-параметр iframe в корневом `index.html`;
2. query-параметр iframe в `miniapp/index.html`;
3. версии подключаемых скриптов в `miniapp/map3d.html`;
4. `SHELL_CACHE` в `service-worker.js`.

Обе страницы должны указывать на одну и ту же версию `map3d.html`. Иначе основная страница и Mini App могут показывать разные сборки. Проверяй именно фактические строки подключения, а не только номера коммитов.

## Обязательная проверка

Выполни:
```sh
node --check miniapp/map3d.js
node --check miniapp/map3d-geometry.js
node --check miniapp/floorplans.js
node --check miniapp/floorplans-building1.js
node --check service-worker.js
node tests/map3d-geometry.test.cjs
```

Далее дождись успешных `Check frontend` и `pages build and deployment` на последнем commit ветки. Проверяй HTTPS-сайт на телефоне, а не только локальный HTML.

Проверь отдельно:
- открытие карты из главной страницы и возврат к расписанию;
- переключение схемы и спутника;
- 3D включается/выключается в обоих режимах, камера наклоняется, здания с известной высотой действительно объёмные;
- активные кнопки читаемы в светлой и тёмной теме;
- маркеры всех корпусов открывают правильные карточки;
- у главного корпуса одно исходное фото, без случайной галереи;
- планы корпусов 1 и 2 открываются, этажи переключаются, схема вписывается целиком, увеличение и выбор кабинета работают;
- на узком мобильном экране элементы не перекрывают карту.

Для Android отдельно проверь workflow `Build Android APK`, скачай свежий артефакт, установи его и проверь на устройстве. Успешная публикация GitHub Pages не обновляет уже установленный APK.

## Как отчитываться

В конце перечисли:
- точную ветку и commit SHA;
- изменённые файлы;
- какие Actions завершились успешно/с ошибкой;
- что реально проверено на опубликованном сайте и на Android;
- что осталось неисправным или не проверено.

Не называй задачу выполненной только потому, что коммит создан или CI прошёл. Отделяй автоматические тесты от визуальной проверки в браузере.
