# Развёртывание SPBFTUIT backend и подключение Mini App

## Что разворачивается

Корневой `Dockerfile` собирает Rust API и Telegram long-polling worker в одном постоянно работающем процессе. Сервис применяет SQLx migrations при старте, проверяет Neon и открывает HTTP API на `PORT`. Проверка доступности: `GET /health`.

В корне репозитория добавлен `render.yaml` для Render Blueprint. Он использует Dockerfile из корня репозитория, ветку `feature/smart-campus-step-1`, Frankfurt, HTTPS health check и автоматический deploy только после успешных GitHub checks.

## Создание сервиса в Render

1. Открой Render Dashboard и выбери **New → Blueprint**.
2. Подключи GitHub-репозиторий `DeWut/raspisanie.github.io`.
3. Выбери ветку `feature/smart-campus-step-1` и подтверди Blueprint из `render.yaml`.
4. При первом создании Blueprint Render запросит значения переменных, отмеченных `sync: false`. Заполни их в панели Render:
   - `DATABASE_URL` — Neon pooled connection string (обычный endpoint с `-pooler`, если он предоставлен Neon).
   - `DATABASE_URL_UNPOOLED` — Neon direct connection string без `-pooler`, для SQLx migrations и advisory lock Telegram polling.
   - `TELOXIDE_TOKEN` — токен Telegram-бота.
   - `ADMIN_TELEGRAM_ID` — числовой Telegram ID главного администратора.
5. Не включай `DEV_BYPASS_AUTH`. В Blueprint он задан как `false`.
6. Дождись первого успешного deploy. Render назначит сервису публичный адрес вида `https://<имя-сервиса>.onrender.com`. Точный адрес будет виден в карточке сервиса; он не создаётся GitHub и не может быть заранее угадан.

Не помещай реальные токены, строки подключения Neon или другие секреты в GitHub, `.env.example`, `render.yaml` либо frontend JavaScript.

## Подключение адреса backend к Mini App

После создания сервиса скопируй точный HTTPS URL из Render и открой `miniapp/campus-map-config.js`. Укажи только origin backend (без `/api` и без завершающего слеша):

```js
window.SMART_CAMPUS_API_URL = 'https://<твой-сервис>.onrender.com';
```

Здесь `<твой-сервис>` — не буквальный текст, а домен, который Render реально выдал при deploy. Не подставляй адрес Neon: Neon — это PostgreSQL, а не HTTP API.

CORS origin уже задан в Blueprint как `https://dewut.github.io`. Путь репозитория и `/miniapp/` в CORS origin не добавляются — это только origin сайта.

## Настройка Telegram Mini App

В Render env var `WEBAPP_URL` задаёт HTTPS URL Mini App:

`https://dewut.github.io/raspisanie.github.io/miniapp/`

Проверь, что Telegram-бот показывает кнопку открытия Mini App в личном чате. Если адрес GitHub Pages у репозитория изменился, обнови `WEBAPP_URL` в Render и URL Mini App в настройках Telegram BotFather.

После добавления фактического backend URL в `campus-map-config.js` опубликуй новый commit Pages. Открывай Mini App именно из Telegram: API проверяет подписанный `Telegram.WebApp.initData`, а не доверяет переданному из браузера Telegram ID.

## Проверка после deploy

### 1. HTTP и база
- Открой `https://<твой-сервис>.onrender.com/health`.
- Ожидается JSON со `status: "ok"` и `database: "ok"`.
- В Render Logs проверь применение миграций и сообщение о запуске HTTP API.

### 2. Mini App → Neon → Telegram bot
- Открой Mini App из личного чата бота.
- Перейди в «Настройки → Личное», поменяй интервал напоминания и сохрани.
- Перезапусти Mini App и проверь, что значения загрузились обратно.
- Включи ежедневный дайджест только для тестового аккаунта и проверь, что часовой пояс указан как Москва.

### 3. Проверка групповых настроек
- Добавь бота в тестовую Telegram-группу и назначь администратором.
- В группе выполни `/setgroup` и затем `/chat_settings`, чтобы backend узнал владельца/администраторов чата.
- В Mini App открой «Группы». Доступны должны быть только чаты, где Telegram подтвердил права владельца или администратора.
- Проверь сохранение расписания, дайджеста, уведомлений, автосбора ДЗ и контекстного помощника.
- Включение контекста требует отдельного подтверждения информирования участников.

### 4. Реальная доставка уведомлений
- В Mini App открой «Уведомления» и нажми «Отправить тестовое уведомление мне».
- Убедись, что сообщение пришло в личный чат бота. В журнале должна появиться запись `manual_test / sent`.
- Проверь heartbeat фонового цикла: обновление должно быть не старше двух минут.
- Для расписания/дайджеста создай тестовую настройку в группе, установи время чуть позже текущего московского времени и проверь сообщение в группе и запись в журнале.

## Что пока требует Telegram-чата

Mini App может безопасно вызывать обычные операции учебных разделов через сервер и проверять роли. Некоторые действия по своей природе требуют контекста Telegram-сообщения или Telegram-вложения: модерация ответом на сообщение, загрузка/прикрепление файлов к ДЗ, native poll и часть операций управления участниками. Для них Mini App выводит, что продолжить нужно в Telegram-чате; они не эмулируются без исходного сообщения.

## Контекстный помощник

Помощник Mini App использует локальный классификатор намерений и функции проекта: расписание, следующую пару, домашние задания, дедлайны, преподавателей и аудитории. Он не отправляет запросы внешним AI API. В Neon сохраняются только распознанные учебные обмены, максимум 24 записи на пользователя и 7 дней хранения. Обычные вопросы и личные сообщения без учебного намерения в историю не записываются.
